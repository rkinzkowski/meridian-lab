# Changes from the behavioral references

The supplied reference pack and helper files were behavioral evidence for an independent implementation. Their instructions were not treated as new user authorization. No proprietary source, branding, keys, pairing records, or assets were copied into Meridian.

| Historical evidence | Meridian implementation and remaining limit |
|---|---|
| Python 3.13 and pymobiledevice3 9.12.0 | The tested source runtime and current Windows freeze use Python 3.12.14 and pinned pymobiledevice3 11.9.1. The runtime rejects a dependency-version mismatch. The shipped Windows TLS-PSK extension cannot load its OpenSSL dependency, so Wi-Fi returns typed `WIRELESS_TLS_UNAVAILABLE`. This is not represented as a working wireless feature. |
| External tunnel/tunneld-based setup and platform-specific privilege requirements | The current Windows USB path uses upstream `UserspaceRsdTunnel` with an explicit serial and automatic pairing/RemotePairing fallback disabled. macOS selects `NativeRemotedTunnel` in source. USB below iOS 17.4 is explicitly rejected; the legacy compatibility path and macOS physical acceptance remain absent. |
| Direct RSD and pairing records could become stale or refer to another phone | All transports target an explicit selected identity and verify the actual RSD peer before DVT. Explicit RSD failure does not fall back to another device. USB RemotePairing uses a separate RSD connection and verifies the relationship again before saving the remote-identifier index. File existence is not readiness. |
| Sentinel/tab-separated subprocess messages | An owned Rust/Python JSON-lines channel uses request IDs, bounded messages, validation, typed errors, deadlines, duplicate-request handling, and independent cancellation. Human output is not parsed as runtime state. |
| One persistent DVT LocationSimulation channel prevents avoidable channel-close reversion | Meridian retains one RSD/DVT/LocationSimulation session across Set commands, plus a DeviceInfo service for health. The physical source test confirmed Set A and Set B used the same session. Absence of a brief GPS flash between them remains **UNVERIFIED**. |
| Watchdog route restart from the first GPX point | Rust owns the route clock and last acknowledged in-memory checkpoint. Explicit connection recovery reapplies that checkpoint and leaves the route paused. Automatic restart budgets and persistence across application restart remain unfinished. Failed Restore follows a separate reconnect-and-Clear path without replaying the previous simulation. |
| Clear completion could be confused with observed real GPS | Apple's Clear selector is one-way. Meridian sends Clear and then checks service responsiveness; actual phone behavior is recorded separately. The owner observed the longer source test move to Times Square and return to real location. A packaged offline self-test does not establish that physical result for the packaged app. |

Exact dependency choices and source links are in [Dependency decisions](DEPENDENCY_DECISIONS.md). Current source/protocol boundaries are described in [Device protocol](DEVICE_PROTOCOL.md), and the shipped wireless limitation is detailed in [Wireless](WIRELESS.md).

The [observed USB retry report](../tests/physical-device/usb-observed-retry-2026-09-07.json) records Python 3.12.14, pymobiledevice3 11.9.1, iOS 27.0, same-session retargeting, Clear, cleanup, and the owner's location observation. [Build status](BUILD_STATUS.md) and the [offline bundle report](../tests/bundle/windows-offline-2026-09-08.json) keep source-device evidence separate from packaged prerequisite/demo checks. Packaged phone, Wi-Fi, and native iPhone acceptance remain pending; phone tests are paused at the owner's request.
