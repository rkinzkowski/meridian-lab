# Development signing and installation

`crates/ios-bootstrap` contains a real optional adapter for idevice 0.1.65 and isideload 0.3.17. Its `signing` feature compile-checks on this Windows host. It is not wired to an Apple-account or installation screen in the desktop application.

The caller must inject an explicit reviewed anisette provider. There is no default external provider. Authentication uses an asynchronous two-factor callback, bounded timeout and in-memory storage; the callback response must be dispatched independently of the waiting authentication future. Teams are listed for explicit selection. Certificate exhaustion returns an error; the adapter does not automatically revoke certificates.

Signing verifies the selected device, verifies the source artifact's size/hash, registers the selected phone, signs with the selected team, and checks the resulting bundle identifier. Installation checks the selected device again and confirms the actual installed bundle through InstallationProxy. Presigned IPA installation is also available with the `device` feature. Configuration placement checks device identity and uses the installed app's House Arrest Documents service, a fixed staging path, byte readback, and rename. These paths have not been exercised against a physical phone.

Compile check: `cargo check --locked --release -p meridian-ios-bootstrap --features signing`.

On a Mac, run `bash apps/ios/build.sh simulator-test` for an unsigned simulator build and XCTest run, or `bash apps/ios/build.sh device-archive` for an unsigned device archive. For a legitimate development IPA, set `APPLE_TEAM_ID` and run `bash apps/ios/build.sh archive`; it exports using `apps/ios/export-development.plist` (override with `IOS_EXPORT_OPTIONS` and `IOS_EXPORT_PATH` when needed). The packet-tunnel target declares Apple's [Network Extensions entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.networking.networkextension), so the account/team must have an App ID and [development provisioning profile](https://developer.apple.com/help/account/provisioning-profiles/create-a-development-provisioning-profile) that authorize this capability; this documentation does not claim that a free or personal team can provision it. No Apple credentials, keys, pair records or compiled IPA are included. There is no working one-click signing CLI/UI to claim as a finished feature.
